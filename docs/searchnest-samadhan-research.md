## SearchNest

- Repository: https://github.com/SanjayPanwar73/SearchNest
- Inspected tree commit: `21787d83cd44ea0ec69d538837b1f9742ea6ceba`.
- Supported purpose: A web search interface and developer search API with account access, credential management, quotas, and request activity.
- Stack verified in `requirements.txt`, `main.py`, and `database.py`: Python, FastAPI, Jinja2, vanilla JavaScript/CSS, SQLAlchemy, Alembic, SQLite by default, PostgreSQL support.
- Search provider abstraction selects a backend-only Tavily or Google Programmable Search adapter. Both adapters normalize results and distinguish credentials, quota, timeout, service, and validation failures. Sources: [search.py](https://github.com/SanjayPanwar73/SearchNest/blob/main/search.py), [providers.py](https://github.com/SanjayPanwar73/SearchNest/blob/main/providers.py).
- Account registration/login uses opaque cookie sessions. Passwords use salted PBKDF2-HMAC-SHA256. Session, CSRF, and API tokens are stored as SHA-256 digests. State-changing dashboard operations require the session plus a CSRF header. Sources: [security.py](https://github.com/SanjayPanwar73/SearchNest/blob/main/security.py), [main.py](https://github.com/SanjayPanwar73/SearchNest/blob/main/main.py).
- API key creation, configuration, activation, revocation and regeneration are implemented; raw keys appear only during creation/regeneration. List views use masked identifiers. Source: [api_key.py](https://github.com/SanjayPanwar73/SearchNest/blob/main/api_key.py).
- Minute, day, and month quota counters are persisted. The route's quota consumer uses database row locking plus a process-local key lock for SQLite and returns a retry interval on rejection. Source: [rate_limit.py](https://github.com/SanjayPanwar73/SearchNest/blob/main/rate_limit.py).
- Browser search includes pagination and explicit empty/error states. Developer dashboard contains usage totals, remaining quota, errors, key management, recent requests and copyable API examples. Sources: [templates/index.html](https://github.com/SanjayPanwar73/SearchNest/blob/main/templates/index.html), [templates/dashboard.html](https://github.com/SanjayPanwar73/SearchNest/blob/main/templates/dashboard.html), [static/search.js](https://github.com/SanjayPanwar73/SearchNest/blob/main/static/search.js).
- Request IDs, structured errors, health endpoint, OpenAPI contracts, and migrations are present. Tests cover authentication/keys, providers, browser/protected search, dashboard/OpenAPI, config, and migrations; tests were not run during this research.
- Useful engineering decision: keep provider credentials server-side and normalize provider differences behind a replaceable adapter; keep developer credentials hashed and reveal their raw value once.
- Suggested short copy: **A developer search platform with provider adapters, hashed API credentials, persistent quotas, and a self-service usage dashboard.**
- Suggested challenge: unify upstream search responses while controlling access and accounting for each developer request.
- Suggested technical result: implemented a common search response contract and an account-to-key-to-request workflow. No measured outcome claim is supported.
- Live URL: none verified. Repository homepage is empty and README links only to local app addresses and third-party documentation.
- Screenshots: no screenshot/image asset files exist in the repository tree. Use a clearly marked product preview if the portfolio renders an illustrative interface; do not call it an actual screenshot.

## Samadhan-Setu

- Repository: https://github.com/SanjayPanwar73/Samadhan-Setu
- Inspected tree commit: `3489b61f94a6c5cd6d98ca2bdd6547b3b88e5920`.
- Supported purpose: Institutional grievance management with AI-assisted categorization, departmental triage, staff workflows, and management oversight. Repository metadata describes a platform for colleges; some source prompts and categories use municipal terminology, so the broader institutional description is safest.
- Stack verified in [frontend/package.json](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/frontend/package.json) and [backend/requirements.txt](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/requirements.txt): React, Vite, React Router, Axios, Tailwind, Python, FastAPI, SQLAlchemy, Alembic, SQLite local configuration/PostgreSQL driver, Transformers, sentence-transformers, FAISS, APScheduler.
- Complaint creation persists a record, classifies its category, retrieves similar complaints, groups related issue roots, computes sentiment and priority, selects a department, and assigns its least-loaded staff member. Source: [complaint_service.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/services/complaint_service.py).
- BART large MNLI performs zero-shot classification across electricity, water, sanitation, roads, safety, noise, telecom, and other. DistilBERT SST-2 supplies sentiment. MiniLM L6 v2 supplies sentence embeddings. Sources: [classifier.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/ai/classifier.py), [sentiment.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/ai/sentiment.py), [embeddings.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/ai/embeddings.py).
- Priority is an explainable formula: 35% severity, 30% people affected, 20% age, 15% repeat count. The API returns component contributions as well as the final 0–100 score. Source: [priority.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/ai/priority.py).
- Role-guarded routes support community users, staff, administrators, and management. Staff mutation/suggestion access is limited to assigned complaints. Status transitions are validated, owners can submit feedback, and a resolved complaint with a rating of 1–2 is reopened and escalated. Source: [complaints.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/routers/complaints.py).
- SLA checks use APScheduler. Overdue pending/in-progress records receive an escalation level, timestamp, and history entry; repeat escalation is throttled by configuration. Sources: [main.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/main.py), [escalation_service.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/services/escalation_service.py).
- A normalized FAISS inner-product index retrieves similar resolved cases above a threshold. Optional Ollama `phi3` generation uses retrieved cases; retrieval still works when local generation is unavailable. Source: [rag.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/ai/rag.py).
- Management endpoints provide grouped priority queues, category distribution, SLA violation counts, and resolution trends. Admin endpoints support managed staff/management creation, workload inspection, assignment, departments, and manual escalation. Sources: [management.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/routers/management.py), [admin.py](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/backend/app/routers/admin.py).
- React application lazy-loads pages behind role protection, with complaint list/detail/new complaint, staff/admin/management views, departments, profile and notifications routes. Source: [App.jsx](https://github.com/SanjayPanwar73/Samadhan-Setu/blob/main/frontend/src/App.jsx).
- Frontend auth and workspace test files exist; evaluation/backfill scripts exist. None were executed, so model accuracy and operational improvement claims are unsupported.
- Useful engineering decision: expose deterministic priority contributions for human review, and let retrieval operate independently of optional local text generation.
- Suggested short copy: **An AI-assisted grievance platform that classifies complaints, explains urgency, routes work to staff, and tracks escalation through resolution.**
- Suggested challenge: convert unstructured complaints into a traceable department workflow while keeping urgency and suggested actions reviewable.
- Suggested technical result: implemented a complaint-to-classification-to-assignment lifecycle with role scopes, history, escalation, feedback reopening, and similar-case retrieval. No measured outcome claim is supported.
- Live URL: none verified. Repository homepage is null; frontend/backend READMEs contain local setup URLs.
- Screenshots: no actual application screenshots in the repository. `frontend/src/assets/hero.png` exists but is a hero asset, not evidence of an application screenshot. `react.svg`, `vite.svg`, favicon and icon sprite are also present.
